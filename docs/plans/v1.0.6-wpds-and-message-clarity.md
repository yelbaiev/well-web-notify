# v1.0.6 — Well Web Notify on the SEO plugin's design system, and messages that read straight

## Why

Three things, one release.

1. **The admin looked nothing like Well Web SEO any more.** SEO moved to WPDS v2 in
   2.24.x–2.25.x: its own top-level menu, sections as sidebar rows, one stylesheet, a
   `.wpds-panel` as the only container. Notify was still on the old `ww-*` cards, and it
   registered itself as a submenu of a shared "Well Web" parent that no longer exists.

2. **Notify's admin JS was breaking the SEO plugin.** `assets/js/admin.js` rewrote
   `#adminmenu` in the browser to force-highlight a "Well Web" parent. SEO's nav settles
   highlighting with the `parent_file` / `submenu_file` filters, and this script ran after
   them and undid the result — the exact failure SEO's `admin-nav.php` documents.

3. **Jetpack submissions arrived half-empty, or with junk.** Reported on lawfirmimperial.com:
   the same form produced a message with one field on one submission and every field plus
   `Entry title` / `Entry permalink` / `Feedback id` on the next.

## The Jetpack bug, exactly

Read from Jetpack 16.2 (`jetpack-forms/src/contact-form/class-feedback.php`):

- `get_all_values()` = compiled fields keyed `"{n}_{Label}"`, **merged with**
  `get_entry_values()` — which adds `entry_title`, `entry_permalink`, `feedback_id`,
  `email_marketing_consent`, sometimes `entry_page`.
- `get_legacy_extra_values()` = the *non-standard* fields only, keyed `"{n}_{Label}"` with a
  counter that continues past the ones already in `$all_values`. So a form with Имя + Телефон
  yields `1_Имя`, `2_Телефон` in all-values and `3_Телефон` in extra-values — the same field,
  twice, under two different keys.
- `class-contact-form.php` writes `_feedback_extra_fields` (the extra values only, so:
  `3_Телефон` and nothing else) at line ~3271, **before** it fires `grunion_pre_message_sent`
  (~3394) and `grunion_after_message_sent` (~3424).

Notify listened on all of them and let whichever arrived first dispatch:

- meta listener wins → message contains `3 Телефон` and nothing else. ← report, message 1
- `grunion_after_message_sent` wins → all-values merged with extra-values → every field, the
  phone twice, plus three internal keys. ← report, message 2

Both symptoms, one cause: several sources of differing quality racing for one dispatch slot.

## What changes

### 1. One dispatch per submission, chosen by quality, at `shutdown`

`WellWeb_Notify_Jetpack` no longer sends from a hook. Each listener *offers* a payload with a
rank (`after_message_sent` 30 > `pre_message_sent` 20 > meta 10 > transition 5). The richest
offer for a given feedback post wins and is sent once on `shutdown`, which still runs after
Jetpack's redirect-and-exit because WordPress registers it with `register_shutdown_function`.

`$extra_values` is no longer merged into `$all_values` — it is a subset of it under different
keys, and merging it is what printed the phone number twice.

### 2. Field normalisation, for every integration, in one place

`WellWeb_Notify_Message::normalize_fields()`, called from `Form_Manager::handle_submission()`:

- strips a leading `"{digits}_"` or `"{digits} "` index from the label (`3_Телефон` → `Телефон`)
- drops internal keys no human asked for — `entry_title`, `entry_permalink`, `feedback_id`,
  `email_marketing_consent`, `entry_page`, `is_block`, `ip`, plus CF7's `_wpcf7*`
- collapses duplicate label+value pairs
- trims, flattens arrays, strips tags, and caps a single value at 500 chars

`entry_title` / `entry_permalink` are not discarded — they are lifted into the message's
*source* (the page the form sits on), rendered once as a link at the foot.

### 3. One message shape, four renderers

`includes/class-message.php` builds a normalised payload — title, site, source, source URL,
fields, phone — and each channel renders that, instead of four channels each rebuilding a
field list from `$meta['fields']` in slightly different ways. What the reader gets:

```
New form submission
lawfirmimperial.com · Военные дела

Имя: Татьяна
Телефон: 0937279861

☎ +380937279861
💬 WhatsApp   ✈ Telegram   📱 Viber

Военные дела →
```

The form name was previously computed into `$subject` and then never shown by any channel.

### 4. WPDS, and Notify's own menu

- `assets/css/wpds.css` — the shared core (tokens + components) vendored from
  `wellweb-seo/assets/css/wpds.css` lines 1–831. `assets/css/wpds-v2.css` — verbatim copy.
  `assets/css/notify.css` — only what is specific to this plugin.
- Top-level menu **Well Web Notify** at position 77 (SEO holds 76), three sidebar rows:
  **Channels**, **Sources**, **Log**. Channels keeps the slug `well-web-notify-settings`, so
  every existing bookmark, notice link and dashboard-widget link still resolves.
- The `#adminmenu` rewrite in `admin.js` is deleted.

## Not doing

- No Overview/dashboard screen. Three screens, and a landing page summarising two of them is
  a screen people click past.
- No change to the channel credentials, encryption, or the log table.
